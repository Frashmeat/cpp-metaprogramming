# 类型计算与实例化

在类型变换、traits、参数包、惰性求值、异构数据或静态行为组合任务中读取。实现依据见 [MP11 与 Hana](sources.md)。本页先给技巧选择表，随后解释类型计算、实例化、对象生命周期和架构取舍。

## 技巧、使用方式、场景、目的与收益

下表收益为满足相应前提时的预期收益；速度、内存和代码体积的改善需要测量。

| 技巧 | 使用方式 | 场景 | 目的 | 收益 |
|---|---|---|---|---|
| Type traits | 使用标准或已有 traits 查询性质、转换类型 | 泛型容器、编码分类、存储适配 | 为约束与实现提供准确类型信息 | 减少重复检测，集中表达类型规则 |
| decltype / declval | 在未求值上下文查询实际表达式类型 | 回调结果、成员访问、泛型返回类型 | 从操作推导类型关系 | 避免手工同步结果类型，不必实际创建对象 |
| 元函数与模板别名 | 将输入类型映射到结果类型，组合已有操作 | 包装类型、参数适配、结果类型推导 | 封装可复用的类型计算 | 类型规则可组合、可单独验证 |
| 特化与偏特化 | 匹配完整类型或类型形状，并提取参数或提供实现 | 指针、数组、模板实例的适配 | 根据结构区分处理方式 | 减少重复分支，明确特殊类型的规则 |
| 类型列表与类型算法 | 对已有类型载体做映射、过滤、去重和组合 | 消息集合、variant 构造、异步结果类型 | 维护多种类型之间的关系 | 从同一集合派生所需结构，减少多处同步 |
| 惰性实例化 | 用偏特化或延迟元函数隔离潜在非法计算 | 可选成员、条件类型计算、未选分支报错 | 控制类型形成和实例化时机 | 合法输入不被无关分支拒绝，算法更易组合 |
| 参数包展开 | 将同一类型或对象操作应用于多个参数 | 工厂、日志、回调包装、异构容器 | 处理不定数量与类型的输入 | 用共同规则替代固定参数数量的重复实现 |
| 折叠表达式 | 给参数包定义归约操作及必要初值 | 条件合取、累计、逐项访问 | 明确归约和求值规则 | 常见包处理可减少手写递归；空包行为可直接约定 |
| 索引序列与 tuple/apply | 按索引或展开 tuple 调用操作 | 异构字段遍历、参数重排、调用适配 | 连接位置、静态类型与实际对象 | 统一访问不同类型元素，同时保留各自类型 |
| CRTP | 基类通过派生类型复用行为并静态调用 | 运算符补全、固定类型的接口复用 | 在类型已知时共享静态行为 | 提供静态分派和内联机会；性能收益不保证 |
| 策略类设计 | 将真正独立的行为变化作为模板策略组合 | 分配、检查、同步方式可静态配置的组件 | 在编译期组合明确的行为选项 | 配置与类型绑定，可减少重复组件；组合数量需控制 |
| 表达式模板 | 用表达式节点保存运算结构，延迟到合适边界求值 | 数值运算、矩阵/向量表达式 | 合并可融合的计算 | 可能减少中间对象与重复遍历，需以语义和测量确认 |

## 选择计算形式

- 输入/结果都是值时，优先普通 constexpr 算法；需要产生类型时使用模板。
- 类型集合优先保持一个清楚的载体，如项目已有的 `type_list<Ts...>` 或 tuple。能直接展开参数包的操作，不必递归逐项实例化。
- 类型载体不必包含对象。不要仅为获得类型信息就构造对象，从而意外要求默认构造、可拷贝或可析构。
- 组合操作明确输入形状、结果形状及空列表含义。单个元素、重复类型、不可复制类型只在相关时增加覆盖。

下面是完整的 C++17 类型变换示例；映射只形成类型，不构造对象：

```cpp
#include <type_traits>

template<class... Ts> struct type_list {};

template<template<class> class F, class List> struct transform;
template<template<class> class F, class... Ts>
struct transform<F, type_list<Ts...>> {
    using type = type_list<F<Ts>...>;
};
template<template<class> class F, class List>
using transform_t = typename transform<F, List>::type;

struct NoDefault { NoDefault() = delete; };
static_assert(std::is_same_v<transform_t<std::add_pointer_t, type_list<>>,
                             type_list<>>);
static_assert(std::is_same_v<
    transform_t<std::add_pointer_t, type_list<int, const double, NoDefault>>,
    type_list<int*, const double*, NoDefault*>>);
```

## 分支选择不等于延迟形成实参

`std::conditional_t<condition, typename T::value_type, void>` 中，即使 condition 为 false，`typename T::value_type` 仍可能必须先形成。不要用这种写法保护缺少成员的 T。

用偏特化或可延迟求值的元函数，将访问放到有效的分支；已有 MP11 时可考虑 `mp_eval_if`、`mp_defer`。简单检测不必引入库：

```cpp
#include <type_traits>

template<class T, class = void>
struct value_type_or_void { using type = void; };

template<class T>
struct value_type_or_void<T, std::void_t<typename T::value_type>> {
    using type = typename T::value_type;
};

struct WithValue { using value_type = long; };
static_assert(std::is_same_v<typename value_type_or_void<int>::type, void>);
static_assert(std::is_same_v<typename value_type_or_void<WithValue>::type, long>);
```

这是 C++17 检测例子，不代表现代接口应该默认改用 SFINAE。C++20 的候选接口约束通常用 concept 表达。

## 判断失败发生在哪一层

- SFINAE 处理替换的直接上下文。替换触发另一个模板实例化，而其函数体或类定义内部硬错误，不一定能被外层检测吸收。
- requires 表达式也不是捕获所有编译错误的异常处理器。非依赖的非法表达式、内部实例化副作用和不满足语法要求的代码仍可能报硬错误。
- `if constexpr` 的分支丢弃在相应模板实例化条件下起作用；非模板上下文和非依赖名称检查不能一概忽略。
- 若某个分支只应在被选中时有效，让潜在非法操作依赖模板参数并保留在该分支内，不要提前放到无条件返回类型或别名中。

## 参数包与异构对象

- 明确空包含义：一元 `&&`、`||`、逗号折叠有空包规则；一元 `+` 没有。二元折叠的初值还会影响结果类型、重载和运算顺序。
- 区分同时展开多个等长包与笛卡尔积。长度不一致时应在适当边界拒绝，不把编译器错误藏在深层实现中。
- 不把值的计算顺序与模板参数列表顺序混为一谈；依赖顺序的副作用选择有明确求值顺序的表达式。
- 使用 `std::apply`、索引序列或转发时检查返回引用是否指向临时 tuple/表达式节点。表达式模板保存引用可能延长计算，却不会自动延长被引用对象的生命周期。
- 同一对象多次参与展开时，确认是否会被多次移动；不要无条件对每次访问都做完美转发。

## 成本取舍

直接展开可以减少递归深度，但不保证所有编译器上更快。组合爆炸、重复计算、重型头文件和诊断实例化链都可能是瓶颈。性能任务先按 [验证与成本](verification-and-cost.md) 测量，不通过提高模板深度限制掩盖设计问题。

## 静态行为组合的适用边界

- CRTP 需要实际的派生/基类关系和正确的对象使用方式；不能把基类对象任意当成派生对象。只为代码复用时先比较普通组合或自由函数；需要运行期开放类型集合时不能直接用静态分派替代。
- 策略应有真实、可说明的独立变化。多个策略相互依赖时明确其约束，不用不断增加布尔模板参数掩盖职责耦合。改变策略可能改变类型身份、ABI 与编译成本。
- 表达式模板需要处理临时对象、别名及求值顺序。例如赋值目标也是输入时，融合计算可能改变结果；不是所有中间对象都能安全消除。先确认成本存在，再采用必要的拥有值或引用存储规则。
- 函数模板不能偏特化；需要匹配不同形状时选择合适的重载或类模板辅助，不把类模板偏特化规则直接套用。
- 涉及多个职责时按 [技巧组合](technique-composition.md) 检查边界，不因采用某个架构技巧就默认建设通用框架。
