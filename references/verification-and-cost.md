# 验证与编译成本

在选择测试、确认失败边界、评估性能或交付证据时读取。参考 [MP11、mp-units、fmt](sources.md) 的做法；复用项目现有测试框架。

## 按契约选择验证

| 修改对象 | 有意义的证据 |
|---|---|
| 类型变换 | std::is_same / std::same_as 静态断言，相关空输入与边界 |
| concept / 检测 trait | 允许和拒绝的类型；相关 const、引用和值类别 |
| 重载约束 | 用可区分结果验证实际选中哪个重载，必要时检查歧义消失 |
| constexpr 值算法 | 常量表达式结果与边界；若同时支持运行期，再检查运行期结果 |
| consteval / 非法类型 | 独立翻译单元的预期编译失败，且失败原因是目标契约 |
| 异构对象 / 表达式模板 | 生命周期、移动/复制及相关运行期行为；有必要时使用 sanitizer |
| 兼容性 | 任务声称支持且实际可用的标准/工具链验证，不臆测其他环境 |

## 组合与功能验证

单项断言只能证明局部性质。对 [组合功能](technique-composition.md)，按真实依赖选择额外证据：

| 层次 | 何时需要 | 验证内容 |
|---|---|---|
| 组件边界 | 约束、对象访问或类型结果在组件间传递 | 实际重载、实例化路径、扩展优先级及所有权 |
| 完整路径 | 多个组件共同实现用户行为 | 真实输入到输出和错误路径，不只逐个测试组件 |
| 独立预期 | 编解码、正反转换或同源生成可能共享同一缺陷 | 预期输出或独立校验，不能只靠往返一致 |
| 代表性规模 | 任务涉及性能或有组合增长风险 | 类型数量、字段规模、嵌套等实际变化下的成本 |
| 多翻译单元 | 头文件定义、实例化、配置或链接发生变化 | 实际编译/链接与相关 ODR 风险 |

收益标记为预期、原型已观察或目标环境已验证。输入语义错就回查契约，组件组合错就回查边界，成本不满足就定位热点；无需每次推翻全部设计。

文档示例和局部编译测试通过，不能证明 Agent 在任意大功能上会做出正确决策。技能结构检查、技术示例验证、完整功能验证和实际使用效果分别报告。

## 约束拒绝的测试上下文

在非模板上下文直接写非法 requires 表达式不一定得到 false。验证依赖表达式的拒绝行为时，使用模板化 concept/检测器；若错误出自内部硬实例化，则需要独立编译失败用例。

## 预期编译失败的可靠判定

1. 先让同样包含路径、标准和选项的合法对照编译成功。
2. 每个失败文件聚焦一种违规输入，避免一个错误掩盖另一个。
3. 确认诊断对应目标类型、调用点或约束；缺头文件、编译器启动失败、链接错误或无关语法错误都不算通过。
4. 不依赖整段诊断文本逐字相同。项目需要自动化时使用其既有 compile-fail 机制，并检查稳定的语义标记。

局部只检查声明、约束或实例化时，Clang/GCC 可使用 `-fsyntax-only`，MSVC 可使用适合其模式的语法检查方式。运行行为、符号定义或链接是任务一部分时，这种检查不充分。

## 性能问题先建立可比较基线

记录：编译器与标准库版本、标准、优化/调试选项、PCH/模块状态、输入规模、构建方式和所测指标。不得把旧缓存命中与新全量编译直接比较。

- Clang 的 `-ftime-trace` 可帮助定位解析、实例化及常量求值成本；GCC 的 `-ftime-report` 提供阶段信息。以实际版本支持为准。
- 使用 ClangBuildAnalyzer 前，确认构建确实产生了它需要的 trace 文件；工具不会自动替代编译器的跟踪配置。
- 实例化数量、嵌套深度、峰值内存、总耗时是不同指标。数量减少不能自动证明耗时或内存减少。
- 声称运行期优化时，使用代表性负载，防止死代码消除，并区分编译优化与语言保证。
- 若墙钟时间接近噪声，应重复必要样本并报告波动；不要据一次微小差异下结论。

优先调查实际热点：重复重型实例化、参数组合爆炸、过早求值、重型头文件、无关候选重载，以及过大的 constexpr 工作量。只针对证据支持的瓶颈调整。

显式实例化有适用条件：定义必须在相应实例化点可见，客户端可见性、实例化集合、链接和 ABI 都需要考虑；不能对所有头文件模板统一套用。

## 证据边界

- `clang++` 与名为 `g++` 的命令可能是同一编译器包装器；比较实际版本和目标，不按命令名计数。
- 小例子通过支持局部语义判断，不能证明完整库、全部输入或所有编译器正确。
- 未安装的工具链如实列为未验证，不自动安装大量依赖以凑齐测试矩阵。
- 多编译器、完整构建、全量测试或基准体系是否需要，由改动风险和用户任务决定；不新增无实际收益的门禁。

交付应给出实际命令/配置、成功与失败用例各自验证了什么，以及仍未验证的部分。
